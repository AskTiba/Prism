| 2026-06-28 | tRPC calls return 401 on all requests after SSR, despite valid session (`/api/auth/session` returns 200) | `auth()` from NextAuth v5 breaks inside tRPC's `fetchRequestHandler`. Three failed approaches: (1) calling `auth()` inside `createContext` — async context lost via `next/headers`; (2) calling `auth({ req, res })` at handler level — triggered JWT rotation, old token invalidated before browser received new `Set-Cookie`; (3) cookie merge — still had intermittent failures. | Replaced `auth()` with `getToken` from `next-auth/jwt` in the tRPC route handler, using explicit `salt: 'authjs.session-token'`. `getToken` reads the JWT directly from the request cookie without triggering Auth.js's internal request pipeline or JWT rotation. | Use `getToken` instead of `auth()` in Route Handlers where the async context may not be preserved (tRPC adapters, custom handlers). Log all caught errors instead of silent `.catch(() => null)`. |
| 2026-06-28 | Multiple test files fail after currency format change — `getByText('UGX\u00a01,150')` exact string with non-breaking space doesn't match DOM | RTL's `getByText` with literal string containing `\u00a0` fails because DOM may use different whitespace handling | Replaced all 10+ test files' exact string matchers with regex `/UGX\s*1,150/` | Always use regex matchers for formatted currency values in tests |
| 2026-06-28 | `AUTH_URL` undefined in dev causes session cookie validation to fail | `next.config.ts` had `AUTH_URL: process.env.VERCEL_URL ? ... : process.env.AUTH_URL` — no fallback for local dev. `.env` also lacked `AUTH_URL`. | Added `|| 'http://localhost:3000'` fallback in `next.config.ts` and `AUTH_URL="http://localhost:3000"` to `.env` | `AUTH_URL` must always be set — either via env, config fallback, or middleware — especially in dev where `VERCEL_URL` is absent |
